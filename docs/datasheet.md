# DriftBench-CF datasheet

Following the "Datasheets for Datasets" template.

## Motivation

DriftBench-CF exists to give **ground-truth risk and ground-truth intervention
effects per prefix** for goal drift in long-horizon agents. Existing agent
monitoring benchmarks provide only observed outcomes. That makes it
impossible to tell whether an alert would have rescued a run or broken one
that was going to succeed.

## Composition

| File | One row per | Contents |
| --- | --- | --- |
| `trajectories.jsonl.gz` | agent step | logging schema v1: action, observation, reasoning, tool, virtual clock, fidelity, violation, drift type |
| `prefixes.jsonl.gz` | forked prefix | risk label with Wilson interval, per-arm benefit, rescue, disruption, compliance, raw outcome matrix, fork seeds, onset interval of the run, state at the prefix |
| `splits.json` | split | run ids for train, calibration, test and out-of-distribution test |
| `manifest.json` | dataset | config, config hash, counts, realised agent steps, stop-rule outcome |

v1 (synthetic, default config) has 220 runs and 1,179 labelled prefixes.
That covers 4 environments x 11 agents x 5 drift types, with 6 forks per arm
over 5 arms and a 20-step horizon, for about 0.44 million agent steps.

**Labels.**

- `risk`: fraction of no-intervention forks that violate within H steps.
- `arms[s].benefit`: paired risk difference.
- `arms[s].rescue` and `arms[s].disruption`: seed-level potential outcome
  pairs (spec, section 4).
- `arms[s].compliance`: change in post-intervention fidelity relative to
  seed-matched controls.
- `onset`, `onset_ci`: hinge-model onset of the run's fidelity decline.

## Collection process

Runs are generated by `horizonguard data --config configs/driftbench.yaml`.
Prefixes are chosen by a regular grid plus adaptive points where fidelity
falls. Each prefix is reached by deterministic replay and forked with common
random numbers (spec, section 7). Generation is staged, with a budget stop
rule.

## Agents and environments

The v1 agents are **synthetic**. They are parameterised stand-ins for model
families, with controlled susceptibility, compliance and disruption, so the
pipeline and its statistics can be validated before LLM agents are added.
Results on v1 say nothing about any real model. LLM agents plug in through
`horizonguard.agents.LLMAgent` with a seed-keyed cache. Agents with hidden
provider state are excluded from counterfactual labels.

## Quality

See [`label_noise.md`](label_noise.md). In v1, fork noise is calibrated:
predicted benefit SE 0.145 against an observed replicate noise SD of 0.137.
Test-retest correlation is 0.91 for risk and 0.80 for benefit. Effect
heterogeneity is significant for every intervention strength.

## Splits

Splits are always by run, never by step. The default split holds out the
`ember` family and the `context` drift type as an out-of-distribution test
set, and splits the rest 60 / 20 / 20 into train, calibration and test.
Leave-one-out splits exist for family, scaffold, environment and drift type.

## Uses

Intended uses:

- training and evaluating drift forecasters, intervention-effect models and
  certified alert policies;
- studying when intervening hurts.

Not intended for: claims about specific deployed models, or measuring the
safety of real systems.

## Distribution and licence

Code is MIT-licensed. Generated data carries the same licence. Large files are
versioned with DVC (`dvc.yaml`) rather than git.

## Responsible release

The environments simulate harmless office tasks. Violations are symbolic
actions such as `apply-leverage`, and nothing in the data gives operational
uplift. The stealth-drift adversary (Phase 9) is not part of this release. It
is gated behind a separate review.

## Maintenance

Versioned through `manifest.json` (`version`, `config_hash`). Any change to
labelling code bumps the minor version, and any change to the estimands
bumps the major version.
